# IT 기술 문서 작성·윤문 처방집 (Tech Writing Playbook)

## Contents

- 작성 원칙
- 1. 카테고리별 치환 레시피
- 2. 장르별 골격 템플릿 (작성 모드)
- 3. 보존 대상 (윤문 금지 — Do-NOT)
- 4. 장르별 미세 조정 표
- 5. 재작업 루프 (strict 모드)
- 버전 노트

`tech-doc-writer` 에이전트가 탐지 리포트를 보고 실제 문서를 작성·수정할 때 따르는 처방집. `tech-doc-taxonomy.md`의 패턴별 처방을 **실행 가능한 레시피 + 장르별 골격**으로 확장한다.

## 작성 원칙

1. **정확성 최우선(Accuracy First)**: 코드·명령·수치·식별자·버전·API 시그니처는 100% 정확. 윤문 시 사실 불변.
2. **실행가능성(Runnable)**: 독자가 복사-실행으로 같은 결과에 도달할 수 있게.
3. **구조는 자산(Structure is Good)**: 헤딩·목록·표·코드블록을 적극 활용. 제거하지 않는다.
4. **모호성 제로(No Vagueness)**: 평가절하·막연 표현 금지.
5. **장르·독자 유지(Tone Match)**: 입력 장르·독자 레벨에서 이탈하지 않는다.
6. **근거 기반(Span-Grounded)**: 윤문 시 모든 변경은 탐지 리포트 span에 연결.
7. **날조 금지(No Fabrication)**: 작성 모드에서도 없는 사실을 만들지 않는다. 불명확하면 `<!-- TODO -->`.

## 1. 카테고리별 치환 레시피

### A. 번역투

| 원문 패턴 | 윤문 예시 |
|---|---|
| ~에 대해 설명한다 | ~를 설명한다 |
| ~를 통해 (남발) | ~로 / ~해서 / ~을 호출해 |
| ~에 있어서 | ~에서 / ~할 때 |
| 테스트를 수행한다 | 테스트한다 |
| 설정을 가지고 있다 | 설정한다 / 설정이 있다 |
| ~되어진다 | ~된다 |
| X에 의해 처리된다 | X가 처리한다 |
| It is recommended that you X (agentless) | We recommend X / 그냥 X (명령형) |
| 이는 ~를 제공한다 / This provides | ~를 쓰면 ~할 수 있다 |
| 이 설정은 캐시를 비활성화시킨다 (사역) | 이 설정을 켜면 캐시가 비활성화된다 |
| 오류는 ~를 말해준다 (인격화) | 오류 메시지로 ~를 알 수 있다 |
| 디플로이먼트/이니셜라이제이션 | 배포 / 초기화 |
| Exception을 던진다 / 에러를 발생시킨다 (동사 calque) | 예외를 일으킨다 / 에러가 난다 |
| 모든 사용자들이 / 데이터들 (잉여 '-들') | 모든 사용자가 / 데이터 |
| 함수를 호출한다. 그것은 값을 반환한다 (잉여 지시어) | 함수를 호출하면 값을 반환한다 |

- **EN 직역 환원**: "by means of X" → "with X" / "in order to" → "to" / "is handled by Y" → "Y handles".
- **무생물 주어(A-15)**: technical-writing.dev/sentence는 "도구나 기술, 시스템을 행동의 주체로 사용하지 않아요"·"능동형으로 표현해요"라고 본다 — *도구를 능동 행위 주체로 세우는 문장*(This shows/allows/enables, "이 설정은 ~시킨다")을 교정 대상으로 삼는다. **보존 예외**(이 스킬 판단): 반환한다·발생한다·포함한다류 자연 무생물 주어, 도구가 자연 자동사·피동으로 서술되는 경우("로그가 자동 수집된다")는 *행동 주체*가 아니므로 손대지 않는다.
- **잉여 표지 vs 모호 대명사**: 대상이 *자명한* 잉여 '-들'·지시어는 삭제(A-21)하지만, 대상이 *둘 이상이라 모호한* 대명사는 명사로 **복원**한다(B-5) — 정반대 처방이니 혼동 금지.

### B. 모호성 → 구체화

| 모호 | 구체 |
|---|---|
| 쉽게 / 간단히 / 그냥 | (삭제) + 실제 단계 |
| 여러 / 다양한 옵션 | 세 가지 옵션(A·B·C) |
| 위에서 설명한 | 2.1절에서 설명한 / (앵커 링크) |
| 빠르게 응답 | p95 50ms 이내 응답 |
| 최근 버전 | v2.3 이상 |
| 이것을 설정하면 | 타임아웃 값을 설정하면 |
| 일반적으로 보통 대체로 ~한 편 (헤지 적층) | 캐시 적중 시 5ms (헤지 1개 이하·정량화) |
| 장단점이 있다 / 상황에 따라 다르다 (가짜 균형) | 읽기 위주면 A, 쓰기 위주면 B (판단 기준 명시) |

- **과소 단언(B-7)**: 헤지어는 1개 이하로 축약하거나 수치로 대체. 결정이 필요한 자리(RFC·리포트)는 "장단점이 있다"로 끝내지 말고 조건부 권고를 단다. 단 판단 기준이 입력에 없으면 날조하지 말고 `<!-- TODO -->`.

### C. 코드·예제

- **언어 태그**: 모든 코드펜스에 언어 명시. 셸은 ` ```bash `, 출력은 ` ```text ` 또는 별도 "출력" 블록.
- **플레이스홀더 컨벤션**: `<UPPER_SNAKE>` 한 가지로 통일하고 첫 등장 시 "발급받은 키로 교체" 안내.
- **위험 명령**: 비가역 명령은 경고 블록(`> WARNING` 또는 "주의:")으로 감싸고 영향 범위·복구 가능 여부 명시.
- **비밀정보 치환(C-7)**: 코드·환경변수에 실제 키·토큰·비밀번호·사설키가 박혀 있으면 플레이스홀더(`<API_KEY>`·`AKIAIOSFODNN7EXAMPLE`·`***`)로 redact. Do-NOT의 유일한 예외다(§3 참조). 노출 키엔 "즉시 회전(rotate)" 권고 주석.
- **기대 출력**: 명령 다음에 성공 시 출력 예시를 붙여 검증 가능하게.
- **본문<->코드 일치(C-5)**: 산문에 쓴 식별자·버전·동작이 코드·설정·주석과 어긋나면 결함. 어느 쪽이 정답인지 불명확하면 임의 변경 말고 `<!-- TODO: 불일치 확인 (본문 18 vs package.json 16) -->`. 주석은 코드 내부라 사실 변경 금지, 본문 측 교정 우선.
- **미완결 스니펫(C-8)**: 형식은 맞아도 import 누락·미선언 변수(`client`·`db`)·잘린 `...`으로 복사하면 깨지는 코드는 최소 완결 형태로 보강하거나 "앞선 설정 가정" 1문장 + 전체 예제 링크. **새 API·인자 날조 금지** — 불명확하면 `<!-- TODO: 누락 import 확인 -->`.

### D. hype·관용구 제거

| 원문 | 처리 |
|---|---|
| 강력한 / 혁신적인 / 매끄러운 | 삭제 후 구체 기능·수치 |
| 본질적으로 / 핵심적으로 | 삭제 |
| 주목할 만하다 | 삭제 후 내용 직접 |
| ~의 세계로 떠나봅시다 / dive into | "이 절에서는 ~를 다룬다" |
| 딥다이브해 봅시다 / 심도 있게 파헤치다 / take a deep dive (2025–26 변종) | "이 절에서는 ~ 세 가지를 설명한다" |
| 단순한 X가 아니라 Y다 / not just X, it's Y (안티테제, S1) | 대조 틀 제거, 긍정 절만 직설("분산 일관성을 보장하는 캐시 계층이다") |
| 아시다시피 / 놀랍게도 / As you know (메타담화) | 삭제 후 내용 직접. 독자 상태 단정 금지 |
| 그럼 시작해봅시다 | 삭제 |
| 결론적으로 (남발) | 1회로 제한 또는 "요약" 절로 |

### E. 구조 보강 (제거가 아니라 추가)

- **절차 → 번호 목록**: 순서가 의미 있으면 `1.` `2.` `3.`. 병렬이면 불릿. 순서 메타부사(먼저·다음으로·그다음) 연쇄는 목록화하면 자동 제거된다(E-1).
- **비교 → 표**: 옵션·파라미터·상태 코드·트레이드오프는 표로.
- **헤딩 위계**: H1(제목) → H2(절) → H3(하위). 점프 금지.
- **긴 문단 분할**: 한 문단 한 주제. 5문장 넘으면 쪼갠다.
- **구조 과잉 역가드(E-6)**: 1~2문장이면 될 산문을 단어 조각 불릿으로 부수지 않는다. 관계 없는 짧은 불릿은 산문으로 병합("의존성이 없고(번들 12KB) p99 5ms로 응답한다"). 3단계 초과 중첩은 H3 절·표로 평탄화, 마커 1종·들여쓰기 2/4칸 일관. 판단 기준: 항목이 완결 문장이거나 표가 더 나으면 유지, 단어 조각이면 병합.
- **긴 문서 ToC(E-7)**: H2 6개 이상 가이드·RFC·리포트는 상단 목차를 단다. 상호참조는 앵커 링크, 같은 개념 헤딩 표기 통일. **짧은 README·블로그는 강요하지 않는다(YAGNI)**.
- **콜아웃 격상(E-8)**: 경고·주의·팁·중요·전제가 평문에 매몰되면 콜아웃 블록으로 격상 — `> [!WARNING]`·`> [!NOTE]`·`> [!TIP]`·`> 주의:`. 타입은 문서 전체 일관. **위험 *명령*은 C-6, 비명령 경고(데이터 손실·요금·보안)는 E-8.** 단서어 없는 문장을 의미만으로 경고 판단하지 않는다(과발화 방지).

### F. 용어 일관성

- 문서 시작 시 핵심 용어 1개 표기 확정 → 전체 일괄 적용.
- 한글+영어 병기는 첫 등장 1회만.
- 약어는 첫 등장 풀이("지속적 통합(CI)") 후 약어.
- **외래어 한글 표기(F-7)**: 프런트엔드/프론트엔드처럼 흔들리면 한 표기로 통일하되 **사용 빈도가 높은 쪽**을 따른다(국립국어원 표기법은 빈도 비슷할 때의 2차 기준). 코드·식별자 내 표기는 Do-NOT. (출처: technical-writing.dev/sentence — "외래어 표기는 사용 빈도를 고려하세요")
- **EN locale 철자(F-6)**: color/colour, initialize/initialise를 한 locale(기본 US)로 통일. **코드·식별자·API 시그니처·문자열 리터럴 내부 철자는 절대 보존**(`behaviour`가 API명이면 유지). 날짜 재포맷·Oxford comma는 비대상(추론·날조 위험).

### G. 전제·독자

- 가이드·튜토리얼은 첫머리에 **전제 블록** 필수: 버전·OS·사전 설치·권한·예상 소요시간.
- 미정의 용어는 첫 등장 시 1문장 정의.

### H. 능동·간결

- 문두 접속사 정리, 명령형 통일("클릭하세요" 또는 "클릭한다" 중 하나).
- "~할 수 있습니다" → 단언/명령. "~라는 것" → 직접 명사·동사.
- **EN wordiness 1:1 축약(H-4)**: in order to→to, due to the fact that→because, in the event that→if, has the ability to/is able to→can, a large number of→many, at this point in time→now, for the purpose of→to.
- **명사화 → 본동사**: perform an installation of X→install X, make a configuration change→reconfigure, provide support for Y→supports Y.
- **시제 직역 → 현재형**: "반환할 것이다"→"반환한다"(일반 사실·동작). 미래 시제는 실제 로드맵 약속에만 유지.

### I. 문서 위생

- **em-dash 과용(I-5)**: 쉼표·괄호·콜론 대신 남발한 em-dash(—)는 문맥 부호로 환원 — 부연은 쉼표/괄호, 전환은 마침표로 문장 분리("이 함수는 — 사실상 — 모든 요청을 처리한다" → "이 함수는 사실상 모든 요청을 처리한다"). 한 문단 1회 이내. **Do-NOT carve-out:** 옵션 플래그(`--flag`)·수치 범위(`1—10`)·코드 내부 대시는 보존.
- **내부 참조·앵커 무결성(I-6)**: 헤딩·절을 재배치했으면 그 헤딩을 가리키던 **모든 앵커·"N절 참조"·"위 표 참조"를 함께 갱신**한다(이 스킬은 윤문 중 자기유발 위험 큼). 대상이 사라졌으면 교정·제거, 못 찾으면 `<!-- TODO: 참조 대상 누락 -->`.
- **마크다운 접근성(I-7)**: 이미지 alt는 정보로 채움("![아키텍처: 클라이언트 → API 게이트웨이 → PostgreSQL](./diagram.png)"), 순수 장식만 빈 alt 허용. 링크 텍스트는 목적지 명사구로("자세히는 [여기]" → "[설치 가이드] 참고"), 생 URL은 의미 텍스트로 감쌈(명령 안 URL은 인라인 코드 유지).

## 2. 장르별 골격 템플릿 (작성 모드)

### 개발 가이드·튜토리얼
```
# 제목 (무엇을 만드는가)
> 전제: 버전·OS·사전 설치 / 예상 소요: N분
## 개요 (결과물 1~2문장 + 스크린샷/결과 미리보기)
## 1. 설치
## 2. 설정 (코드블록 + 기대 출력)
## 3. 실행 (명령 + 검증)
## 트러블슈팅 (증상 → 원인 → 해결, 표)
## 다음 단계 (링크)
```
- **polish 모드 체크**: 전제 블록(G-1)·기대 출력(C-4)·위험 명령 경고(C-6) 존재 여부, 절차가 번호 목록인지(E-1). H2 6개+면 ToC(E-7).

### API 문서·레퍼런스
```
## 엔드포인트 / 함수 시그니처
## 파라미터 (표: 이름·타입·필수·기본값·설명)
## 요청 예제 (언어별 코드블록)
## 응답 예제 (성공 JSON)
## 에러 (표: 코드·의미·대응)
## 비고 (rate limit·인증·버전)
```

### README
```
# 프로젝트명 (한 줄 소개)
[배지]
## 빠른 시작 (3~5줄 명령)
## 설치 (전제 + 단계)
## 사용법 (최소 예제)
## 설정 / 옵션 (표)
## 기여 / 라이선스
```

### 테크 블로그
```
# 제목 (구체적 문제·결과)
## 배경 (왜 이 문제, 1~2문단)
## 접근 (시도와 근거, 코드 예제)
## 결과 (수치·벤치마크·전후 비교)
## 정리 (배운 점 + 한계)
```
- hype 절제, 과장 없는 1인칭 가능, 코드는 실행 가능하게.
- **polish 모드 체크**: 안티테제 틀(D-8)·진입 상투구(D-5)·메타담화(D-9)·em-dash 과용(I-5) 제거. 단언엔 근거(B-6), 코드 스니펫은 완결(C-8).

### 기술 리포트·설계서(RFC)
```
## 요약 (TL;DR)
## 배경·문제 정의
## 제안 (설계 + 다이어그램)

## 트레이드오프·리스크

```
- 중립 톤, 근거·출처 명시, 의사결정 가능하게. "장단점이 있다"로 끝내지 말고 조건부라도 권고를 단다(B-7). 결정 못 한 쟁점은 숨기지 말고 "미해결 질문"으로 분리 — 단, 없는 답을 지어내지 않는다(철칙 7).
- **polish 모드 체크**: 결론/권고 절이 비어 있거나 헤지로만 끝나면 B-7. ToC·앵커 무결성(E-7·I-6) 점검.

## 3. 보존 대상 (윤문 금지 — Do-NOT)

이들은 문체상 어색해 보여도 **건드리면 의미·동작이 바뀐다**:

- 코드블록·인라인 코드 내부 전체
- 명령어·플래그·환경변수·경로·식별자
- 수치·버전·날짜·단위·벤치마크 값
- URL·정규식·JSON/YAML 키
- 큰따옴표 직접 인용, 라이선스·법률 조문
- 표준 약어(API·HTTP·SDK·CI/CD 등)
- 옵션 플래그의 `--`, 수치 범위 `1—10`, 코드 내부 대시 (I-5 em-dash 정리의 carve-out)

> **Do-NOT 단 하나의 예외 — C-7(비밀정보 노출):** 코드·환경변수에 **실제** 비밀(AWS 키 `AKIA…`, 토큰 `sk-…`/`ghp_…`, 비밀번호, 사설키, 실접속 문자열)이 박혀 있으면 플레이스홀더(`<API_KEY>`·`***`)로 **치환(redact)**한다. 이때만 코드 내부 수정이 허용된다. 노출된 키엔 "즉시 회전(rotate) 권고" 주석을 남기고, 명백한 placeholder 외의 가짜 비밀은 지어내지 않는다.

## 4. 장르별 미세 조정 표

| 장르 | 허용 | 금기 |
|---|---|---|
| 가이드·튜토리얼 | 번호 목록, 명령형, 전제 블록, 기대 출력, 콜아웃 격상(E-8) | "쉽게/그냥", 전제 누락, 위험 명령 무경고, 미완결 스니펫(C-8) |
| API 레퍼런스 | 파라미터·에러 표, 정밀 명세, 코드 예제 | 서사체, hype, 비일관 표기, 본문<->코드 불일치(C-5) |
| README | 배지, 빠른 시작, 최소 예제, alt·링크 텍스트 충실(I-7) | 장황한 서론, 미완성 TODO 방치, 짧은데 ToC 강요(E-7 YAGNI) |
| 테크 블로그 | 1인칭, 흐름, 근거 있는 주장 | 과장(hype), 근거 없는 단언, dive-into 상투구, 안티테제(D-8)·메타담화(D-9)·em-dash 과용(I-5) |
| 기술 리포트·RFC | 중립 톤, 트레이드오프 표, 출처, 미해결 질문 | 감정·과장, 결론 없는 나열, 헤지로만 종결(B-7) |
| 업무 문서 | 두괄식, 실행항목 표, 간결 | 모호한 요청, 기한 누락 |

작성·윤문 전 입력 첫 300자 + 지시문으로 장르를 추정한 뒤 이 표로 허용/금기 선을 조정한다.
