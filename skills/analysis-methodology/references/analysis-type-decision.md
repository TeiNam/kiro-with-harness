# 분석 유형 결정 트리

질문의 성격에서 기법으로. "무슨 알고리즘"이 아니라 "이 상황엔 이 접근"의 판단 가이드.
구현 코드는 `python-data-analysis` 로.

## 최상위 분기: 질문이 무엇을 원하나

```
질문
├─ "지금/과거 상태가 어떤가?"           → 기술(descriptive)
├─ "왜 이렇게 됐나?"                     → 진단(diagnostic)
├─ "이 차이/관계가 진짜인가(우연 아닌가)?" → 추론(inferential)
├─ "앞으로 어떻게 될까?"                 → 예측(predictive)  ※ mle-workflow
└─ "X 가 Y 를 일으켰나?"                 → 인과(causal)      ※ experiment-design.md
```

## 기술 통계 (descriptive)
- **목적**: 현재 상태 요약. 분석의 항상 첫 단계.
- **도구**: 요약통계(평균·중앙값·분위수), 분포(히스토그램·박스플롯), 시계열 추세.
- **판단**: 평균만 보지 말고 **분포·꼬리·결측**을 항상 확인. 왜도가 크면 중앙값이 대표값.
- **함정**: 집계가 세그먼트 차이를 숨긴다(Simpson's paradox) → 세그먼트별로도 본다.

## 진단 (diagnostic) — "왜"
- **기여도 분해**: 변화량 = 물량효과 + 단가효과 + 믹스효과. 무엇이 얼마나 기여했나.
- **세그먼트 드릴다운**: 전체 → 지역/채널/코호트로 쪼개 어디서 변화가 왔나.
- **선행지표**: 결과 지표가 움직이기 전 움직인 지표를 찾는다(상관은 인과 아님, 가설일 뿐).

## 추론 (inferential) — "진짜인가"
그룹 비교·관계 검정. **기법 선택은 데이터 형태가 정한다:**

| 상황 | 검정 |
|------|------|
| 두 그룹 평균 비교(연속형) | t-test (정규성 가정). 정규성 깨지면 Mann-Whitney U — 단 이건 평균이 아니라 **분포/순위 차이** 검정이라, "위치 이동"으로 해석하려면 두 분포 모양이 비슷하다는 추가 가정이 필요 |
| 3+ 그룹 비교 | ANOVA (평균, 정규성·등분산 가정). 깨지면 Kruskal-Wallis — 역시 평균이 아닌 **분포/순위** 검정 |
| 범주형 두 변수 독립성 | 카이제곱 |
| 두 연속형 관계 | 상관(Pearson/Spearman) → 필요시 회귀 |
| 비율 비교(전환율 등) | 비율검정 / 카이제곱 |

- **효과크기를 함께**: p값은 "우연인가"만 답한다. Cohen's d·상대위험도 등으로 **크기**를.
- **표본 크기**: 너무 작으면 검정력 부족(진짜 효과도 못 잡음), 너무 크면 사소한 차이도
  "유의". 사전 검정력 분석.
- **다중비교 보정**: 여러 검정 시 Bonferroni/BH. 안 하면 위양성 폭증.

## 예측 (predictive) — "앞으로"
- 시계열: 추세·계절성 분해(STL) 먼저. 단순 baseline(naive·이동평균) → ARIMA/Prophet →
  ML 순으로 복잡도 상승. **baseline 을 못 이기면 복잡한 모델은 무의미.**
- 회귀/분류: 프로덕션이면 `mle-workflow`(데이터 계약·검증·서빙). 탐색이면 여기.
- **과적합 경계**: train/test 분리, 시계열은 시간순 분할(미래 누수 금지).

## 인과 (causal) — "일으켰나"
관측 데이터로 인과 주장은 위험. → `experiment-design.md`.
- 무작위 실험이 가능하면 A/B.
- 불가능하면 준실험(DiD·RD·PSM) + 가정 명시.
- 아무것도 안 되면 "상관 관찰, 인과는 미검증"으로 정직하게.

## 선택의 원칙
1. **가장 단순한 기법부터**. baseline·기술통계로 답이 나오면 거기서 멈춘다.
2. **가정을 확인**. 모든 검정·모델엔 가정이 있다(정규성·독립성·등분산). 깨지면 결론도 깨짐.
3. **질문에 답하는 최소 기법**. 화려한 모델보다 결정에 필요한 답.
